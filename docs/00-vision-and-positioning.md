# 00 · 產品定位

## 一句話定位

**「各縣市開放資料的互動小百科」** — 用左地圖右儀錶板的格式，把分散在 20+ 個政府門戶、73,900 筆資料集，整理成「主題 × 縣市 × 指標」的三維可探索儀錶板。

## 為什麼要做

台灣政府開放資料很多，但：
- 一般人不會逛 data.gov.tw
- 同一指標散在 20 個門戶（中央 / 22 縣市 / 部會）
- 資料格式不統一（CSV / XLS / PDF / 各家 API）
- 找到資料也不知道怎麼跟其他縣市比較
- 沒有跨主題視角（例如「水污染裁罰 × 製造業就業」）

本網站把這些痛點包成一個直覺的視覺介面。

## 目標用戶

| 用戶類型 | 使用情境 | 關心什麼 |
|---|---|---|
| **記者 / 內容創作者** | 寫地方議題報導 | 一個縣市的指標全貌、跨縣市排名、敘事性圖表（可截圖） |
| **研究者 / 學生** | 找縣市對齊資料做分析 | 下載 CSV、看資料來源與更新時間、欄位定義 |
| **地方政府工作者** | 看自己縣市在某主題的排名 | 跨縣市比較、歷年趨勢、政策成效 |
| **公民 / 一般民眾** | 好奇自己住的縣市某面向 | 一目了然的視覺、簡單的敘事、不要被資料淹沒 |
| **NGO / 倡議者** | 找議題的縣市落差 | 排名 + 跨主題交叉（如：水污染 × 工業就業） |

> **不是**：學術級研究工具、開放資料儲存庫、原始 API。這些角色由 data.gov.tw / 各部會自家平台扮演。本網站做**體驗層**。

## 與 mini-taiwan 家族區隔

```
mini-taiwan-pos      ── 動態 / 點位 / "現在哪裡有 X"
mini-taiwan-pulse    ── 即時 / 氣象 / "天氣現在怎樣"
mini-taiwan-info ★   ── 統計 / 行政區 / "高雄水資源狀況如何"
```

三個 mini-taiwan 共用：台灣地圖底圖、行政區邊界、時序圖元件、UI 風格指引。
三個 mini-taiwan 不共用：資料時間尺度（即時 vs 月/年）、空間單位（點 vs 行政區）、敘事節奏（瞬時 vs 歷時）。

## 設計原則（給設計師的五條）

1. **地圖永遠在左**（PC 版），高度與右側儀錶板齊。地圖是錨點不是裝飾。
2. **指標卡片可點即可爆炸**。任何看起來重要的數字 / 圖表，都應該回答「點下去會看到什麼更細的」。
3. **資料來源 + 更新時間 + 下載連結**永遠跟著圖表走（信任感是開放資料站的命脈）。
4. **承認沒有的資料**。如果某縣市沒這個主題的資料，明確顯示「資料未開放」並可以連到 data.gov.tw 建議單位開放，不留空白 panel。
5. **不過度動畫**。圖表轉場、爆炸圖展開可以動，但不要 3D 旋轉、不要視差、不要 confetti。要當公民資源不是 portfolio。

## 內容護欄

- ❌ 不做投票預測、政治傾向分析
- ❌ 不做個人化推薦演算法
- ❌ 不爬取需要授權的非公開資料
- ✅ 一律標示資料來源 + 授權條款
- ✅ 提供原始資料下載連結
- ✅ 限制呈現去識別化後的彙整級資料（即便有更細顆粒也不展示）

## 成功指標（KPI）

| 階段 | 指標 |
|---|---|
| MVP 上線 | 完整跑通 1 主題（水資源） × 4 個 view × 22 縣市 |
| 3 個月 | 累計 3 個主題上線、首頁 + 水資源 + 1 個社經/消防 |
| 6 個月 | 5+ 主題、每月活躍 1k UV、被至少 3 篇媒體報導引用 |
| 12 個月 | 10+ 主題、開放 embed 嵌入第三方網站 |
