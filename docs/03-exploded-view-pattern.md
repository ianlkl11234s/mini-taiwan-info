# 03 · 爆炸圖（Exploded View）敘事模式 ⭐

> **核心特色**：任何 KPI 卡片 / 圖表 / 點位都可一鍵「爆炸展開」，把單一數字拆成它背後的維度組成、時間軌跡、空間分布。

## 為什麼要有爆炸圖

每個總體數字（"全國蓄水率 72%"、"高雄今年火警 423 件"）背後都藏著故事：
- **拆組成**：火警 423 件 → 電氣 38% + 縱火 12% + 瓦斯 8% + 菸蒂 6% + ...
- **拆時序**：72% 蓄水率 → 近 30 天怎麼走過來的
- **拆空間**：高雄 423 件 → 38 個區的分布

爆炸圖讓用戶在**同一畫面內**從總體下鑽到細節，不必離開當前 context（不必跳 View C）。

> View C 是「**離開儀錶板進入單一資料集詳情頁**」，
> 爆炸圖是「**在原地把卡片打開看內部**」。
> 兩者並存：爆炸圖快速窺探，View C 完整深入。

## 三種爆炸模式

### 🅐 維度爆炸（Dimension Explode）

把單一數字拆成它的類別組成。

```
[ KPI 卡片：火警 423 件 ]                     [ 點 ⤴ ]
   │
   ▼  展開為長條圖 / 環狀圖
┌─────────────────────────────────────┐
│ 起火原因組成 (423 件)               │
│ ───────────────────────────────────  │
│ 電氣設備   ▮▮▮▮▮▮▮▮▮▮  161 (38%)  │
│ 縱火       ▮▮▮▮         51 (12%)   │
│ 瓦斯       ▮▮▮          34 ( 8%)   │
│ 菸蒂       ▮▮           25 ( 6%)   │
│ 其他       ▮▮▮▮▮▮      152 (36%)  │
└─────────────────────────────────────┘
```

**典型用例**：
- 火警 → 起火原因 22 類
- 水庫蓄水率 → 40 座水庫各自蓄水率
- 人口 → 年齡段組成（金字塔）
- 救護出勤 → 案件類型（OHCA / 創傷 / 其他）

### 🅑 時間爆炸（Time Explode）

把單一時間點數字拆成時序。

```
[ KPI 卡片：蓄水率 72.3% ]                     [ 點 ⤴ ]
   │
   ▼  展開為時序折線
┌─────────────────────────────────────┐
│ 近 30 天蓄水率                       │
│ ───────────────────────────────────  │
│  80% ┐                              │
│      │     ⋱⋱⋱                    │
│  70% │   ⋱      ⋱⋱⋱   (現在)       │
│      │ ⋱            ⋱⋱⋱           │
│  60% └────────────────────────      │
│      4/13          5/13              │
│ ⚠️ 5/2 起連續 7 天無雨              │
└─────────────────────────────────────┘
```

**典型用例**：
- 任何即時 KPI（蓄水率 / 24hr 雨量 / 即時水位）
- 月度 KPI（火警月度件數）
- 年度 KPI（LPCD 歷年）

### 🅒 空間爆炸（Geo Explode）

把縣市總數拆成鄉鎮 / 點位分布。

```
[ KPI 卡片：高雄 423 件火警 ]                  [ 點 ⤴ ]
   │
   ▼  展開為 38 區 choropleth + 排名
┌─────────────────────────────────────┐
│ 高雄 38 區火警分布                   │
│ ───────────────────────────────────  │
│  [小地圖 高雄 38 區著色]            │
│                                      │
│  TOP 5 區                            │
│  鳳山區   58  ▮▮▮▮▮▮▮▮             │
│  三民區   42  ▮▮▮▮▮▮               │
│  苓雅區   38  ▮▮▮▮▮                │
│  ...                                 │
└─────────────────────────────────────┘
```

**典型用例**：
- 縣市總數 → 鄉鎮分布
- 鄉鎮總數 → 村里分布
- 縣市點位 → 群聚熱圖

## 觸發方式（UX 規範）

| 元素 | 觸發 | 視覺暗示 |
|---|---|---|
| KPI 卡片 | 點卡片右上 `⤴ 展開` icon 或整張卡片 | 卡片 hover 時微微抬升 + 右上 icon 浮現 |
| 圖表標題 | 點 `⤴` 切到爆炸模式 | 標題旁灰色 icon |
| 點位 cluster | 點 cluster 圓圈 | hover 時提示「點看分布」|
| 排名長條 | 點任一 bar | hover 時 bar 變色 |

**展開後 → 爆炸圖蓋住原卡片的位置 + 一個 `← 收起` 按鈕**。不要用全屏 modal（會失去 context）。

## 多型支援（Polymorphism）

一個 KPI 可能支援多種爆炸方式 —— UI 上提供 toggle：

```
[KPI: 全國火警 12,304 件]
    ⤴ 展開
    ┌────────────────────────────┐
    │ [按原因] [按時間] [按縣市] │  ← 三個 tab
    │ ────────────────────────── │
    │  (對應的爆炸視圖)          │
    └────────────────────────────┘
```

預設選最有故事性的那個（manifest 裡 `default_explode_mode` 指定）。

## 連續爆炸（Drill-down）

爆炸圖內**還能再爆炸**：

```
全國火警 (123,041 件)
   ⤴ 按縣市
高雄 (423 件)
   ⤴ 按原因
電氣設備 (161 件)
   ⤴ 按月份
2024-08 (32 件) → 切到 View C
```

但層數有上限（建議 3 層），第 3 層後改成「進入 View C」連結。

## 爆炸圖 vs View C 的分工

| 情境 | 用爆炸圖 | 用 View C |
|---|---|---|
| 想快速看 KPI 背後組成 | ✅ | |
| 想下載原始資料 | | ✅ |
| 想看完整欄位定義 | | ✅ |
| 想跨資料集疊圖比較 | | ✅ |
| 想做截圖（單一視覺） | ✅ | |
| 不離開儀錶板大致瀏覽 | ✅ | |

## 設計約束（給設計師）

1. **爆炸圖必須有「← 收起」**，且按 ESC 也能收起
2. **動畫時間 ≤ 350ms**，避免讓人等
3. **爆炸圖的數字單位與母卡片一致**（不要母卡片顯示 `萬人` 子圖顯示 `人`）
4. **「資料來源 + 更新時間 + 下載」隨爆炸圖一起出現**（信任感命脈）
5. **手機上爆炸圖改全屏 sheet**（不是 modal，可上滑收起）
6. **空狀態**：如果某維度沒資料（例：某縣市火警原因缺缺）顯示「資料不足以爆炸展開」

## YAML manifest 對應

每個 KPI / 圖表在 theme manifest 內可宣告 explode 設定：

```yaml
kpis:
  - id: fire_total
    label: 年度火警件數
    unit: 件
    source: fire_incidents_monthly
    explode:
      - mode: dimension
        by: cause  # 起火原因
        default: true
      - mode: time
        range: monthly
        windows: [30d, 1y, all]
      - mode: geo
        level: township  # 鄉鎮分布
```

詳見 04-theme-manifest-spec.md。

## 第一階段 (MVP) 實作建議

不要一次做完三種爆炸：

| Phase | 範圍 |
|---|---|
| MVP (Phase 1) | 只做**維度爆炸 + 時間爆炸** 兩種 |
| Phase 2 | 加入**空間爆炸**（需要鄉鎮邊界資料就緒）|
| Phase 3 | 加入**連續爆炸**（drill-down）|
| Phase 4 | 多型 toggle + 跨主題交叉爆炸（如「水污染裁罰按工業就業排名」）|

爆炸圖是這個產品的「**簽名動作**」，一旦做好就是其他開放資料站難以模仿的差異化。
